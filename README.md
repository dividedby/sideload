# sideload

A CLI that signs and installs apps on your own Apple devices with your own Apple Developer team, using only Apple's
tools (Xcode, `xcodebuild`, `codesign`, `security`, `xcrun devicectl`). This README describes the maintainer's own
setup: **my** devices, **my** paid team, and, as an interim route, my free team, narrowly (see below).

A native Apple Silicon Swift package: a shared core (`SideloadCore`), a JSON CLI (`sideload`) and, later, a
SwiftUI menu bar app (see `docs/design.md`).

**Who it's for.** Anyone with their own Apple Developer team, paid or free, who wants to sign and install apps on their
own devices with Apple's tools. A paid team gets profiles that last a year; a free team works with
Apple's limits (3 apps per device, 10 App IDs per 7 days, 7-day profiles), which sideload tracks and renews around. It is
written for one setup today: the team IDs are constants in `Sources/SideloadCore/Config/Config.swift` and the bundle ID
prefix is set in `config.json`, so fork it and change those for your account. Support isn't guaranteed, but issues and
contributions are welcome and I'll try to get to them; see `CONTRIBUTING.md`.

**Status.** The `sideload` executable runs `doctor`, `device save|list|auto-refresh|slots|lendable|remove`, `canary`, `ledger`, `portal`, `export-cert`, `status`, `inspect`, `fetch`, `updates`, `clean`, `provision`, `sign`, `install`, `refresh`, `app remove` and `slot lend|return`; the automatic `refresh --auto` and `refresh --print-agent` are built, and so are `status --notify` and `status --print-agent`; the owner loads the launchd agents ("Turning on auto-refresh", "Turning on expiry notifications"). The original Node CLI was removed on 2026-10-20 after the Swift
port reached parity (`docs/design.md` section 14). The Swift `canary` is tested with fakes and has had one
owner-run against the real device (2026-10-20: `blocked`, `0xe8008018`, guard passed).

## Purpose

1. Sign and install [Feather](https://github.com/khcrysalis/Feather) on the iPhone; Feather then manages
   other sideloaded apps (Apollo Reborn, Stremio).
2. Export what Feather needs to re-sign on the device: the development certificate as a password-protected
   `.p12` and a provisioning profile covering my devices.
3. Sign and install Stremio on the Apple TV (tvOS).
4. Track certificate/profile expiry (one year on a paid account) and warn well ahead.
5. Interim, while the paid block stands (`provision`, `sign`, `install`, `refresh` (manual, `--auto` and `--print-agent`) and `app remove` are built; the owner loads the launchd agent that runs the automatic refresh, see "Turning on auto-refresh"): re-sign Stremio (iOS and tvOS) and Apollo with the
   free team under `io.github.dividedby.free.*`, and keep them alive across the free profile's 7-day expiry with a
   guarded auto-refresh (`docs/design.md` section 18). sideload has served the Apple TV since 2026-10-24; atvloadly is retired.

## Setup

Requirements: Apple Silicon Mac with Xcode 27 / Swift 6.4 (signed in to the paid team in Xcode > Settings >
Accounts). Node and pnpm are needed only for the secrets hook and its test.

```sh
pnpm install          # no dependencies; enables the pre-commit secrets hook
swift build           # SideloadCore + sideload + SideloadMenu
.build/debug/sideload doctor   # or: swift run sideload doctor
swift test            # Swift Testing suite
scripts/check.sh      # local gate: swift build + test, release build (debug-only hook check), pnpm test (secrets suite), check-secrets --all
```

Save the iPhone once (reads IDs from `devicectl`; nothing is typed into config by hand):

```sh
.build/debug/sideload device save --alias iphone --match "<device name>" --platform ios --yes
```

The canary needs a bundle-ID prefix in `~/.sideload/config.json` (`"bundleIdPrefix": "com.example"`).
It creates an App ID and development profile on the portal, so run it only as the owner (`--keep` leaves the
canary installed):

```sh
swift build -c release --arch arm64
"$(swift build -c release --arch arm64 --show-bin-path)/sideload" canary --device iphone --yes
```

Add `--evidence` to also write a bundle for Apple support when the result is `blocked` or `error`
(never for `working`; opt-in, never automatic). The bundle is built from a fixed list of fields and words, so
an Apple message that contains anything else (a name, a path) is left out and counted, never edited;
`logs/canary-install-*.json` is a local log of the raw devicectl output and is never attached.
`sideload canary history` summarises `logs/canary.jsonl` (no device, no portal): run counts, the last `working` run, the first `blocked` run after it, and what
changed between them (Xcode, macOS, iOS, certificate).

Look inside an IPA before signing it (nothing is installed or sent anywhere):

```sh
.build/debug/sideload inspect ~/.sideload/downloads/Feather.ipa
```

Export the certificate and profile for Feather (owner-run; macOS asks to let `sideload` use the private key:
choose Allow, not Always Allow). Add `--copy-password` only when Feather is open on the iPhone and you are ready
to paste; the command then stays running for 90 s and clears the clipboard itself:

```sh
"$(swift build -c release --arch arm64 --show-bin-path)/sideload" export-cert --device iphone --yes
```

## Menu bar app

`SideloadMenu` is a menu bar app (no Dock icon) that shows the canary state, each saved device's free-account apps (days
left, a time-left bar, free slots, Wi-Fi/USB/offline; read from the ledger's `installs[]` and `slots[]` and checked live against
the device's app list, so an app that is gone shows "Signed · not installed", a lent one "Lent to lab", and a failed renewal a
red "Renewal failed · CODE") and a countdown-ring icon: the ring is the time left of the soonest free install
over its 7 days (label colour; orange when due at 3 days or fewer; red at 1 day or fewer; a dashed red ring with a cross when
expired; a red "!" when the free certificate changed; a dashed grey "?" with no data; a blue arc while a Renew runs). Check status
now, Run doctor (shown inline), Settings… (opens `~/.sideload/config.json`), Open ~/.sideload and Quit need no confirm. The
actions are Renew… (All apps or one app, and Retry on a failed renewal), Install (a signed app the device does not show, or
Install update for a newer signed build), Add app… (an app from `approvedSources` the device does not have: a fetch confirm,
then a second confirm that shows the version and its full SHA-256 and approves that exact version before provisioning, signing
and installing it), Update… (an installed app whose approved source lists a newer version: the row shows "Update available ·
3.9.0 → 3.10.0" and "Update to 3.10.0…" in its menu; the same two confirms as Add app, and the install goes over the app and
keeps its data), Reinstall previous version… (an installed app with an older approved IPA still on disk: "Reinstall previous
version (3.8.0)…" in the row's menu; one confirm with the version and its full SHA-256, then provision, sign that exact version
and install over the app, which keeps its data; no fetch; iOS may refuse an older build, which leaves the installed app as it
is, and renewals keep the version until you update; first run on 2026-10-31: Apollo 4.0.0 over 4.0.1, accepted, still signed in, and Update… back to 4.0.1 after), Remove and "Lendable: <App>". Each opens an inline confirm that says what it will do
(slots, App IDs, the keychain prompt); the confirm button is the owner's `--yes`, and only then does the app run the same
in-process command as the CLI. A running action shows Cancel; the result lists each app with its code, message and fix and a
Retry, or says the lock was busy. A disabled control says why ("Connect iphone over Wi-Fi or USB", "renewable at 6 d left",
"No free slot: remove an app first"). The cert kit Export stays disabled. A pending app-data restore shows as an orange notice with the owner's `slot restore` command. Light and dark follow the system.

The live check is one read-only `devicectl device info apps` per visible device, at launch, on Check status now, and on a panel
open only when the last attempt is 5 minutes old; it takes no lock and writes nothing (`docs/design.md` section 12). When a device
cannot be read (locked, offline, timed out) the card says so once and the rows show the ledger's record. The only network the
panel starts by itself is the update check (`sideload updates` in process: one metadata GET per approved, installed source, at most
every 6 hours, 5 minutes for Check status now); it downloads no IPA and writes only `updates.json`.

Build, install and launch (the build never installs or launches anything; it signs ad hoc, with no identity or Apple ID):

```sh
scripts/make-app.sh                        # prints .build/app/SideloadMenu.app (a release build takes a few minutes)
mkdir -p ~/Applications
ditto .build/app/SideloadMenu.app ~/Applications/SideloadMenu.app
open ~/Applications/SideloadMenu.app       # a countdown ring appears in the menu bar
```

It reads `$SIDELOAD_HOME` (default `~/.sideload`; an app opened from Finder does not see your shell's variables, so use the
default). It loads at launch, when the panel opens and on the refresh button; there are no timers. Run doctor runs the
checks inside the app, so no CLI copy is needed. Each rebuild is a new ad-hoc identity, so macOS may ask again before
the app uses a keychain item. Quit from the panel, or `pkill SideloadMenu`.

| `clean [--yes]` | Implemented; **`--yes` is owner-only**; without it a preview that deletes nothing, which an agent may run. Takes `.op.lock` for the whole run (`OPERATION_IN_PROGRESS`, never waited on); no device, network, keychain, portal or subprocess. Deletes (1) **app-data backups** under `backups/` past 14 days: for a saved device, a backup whose `restoredAt` or `supersededAt` is more than 14 days old (counted from that marker, not from `createdAt`); for an alias no longer saved (`device remove` keeps backups), a backup whose newest of `createdAt`, `restoredAt`, `supersededAt` and `uninstalledAt` is more than 14 days old; and a `.partial` folder older than 14 days. It never deletes a backup `slot restore` would still push, a backup with neither marker, any backup of a device the lab holds or that has an operation in flight (skipped and counted as `devicesSkippedBusy`), a backup with a missing or unreadable manifest (kept and counted as `unreadable`), or anything behind a link. (2) **Downloaded IPAs**: per app it keeps every version recorded as installed on any device, the newest approved version, the approved one before it, and the newest unapproved one while it is newer than the newest approved (it waits for `--approve`); it deletes the other `downloads/<app>/<version>/` folders. A deletion that fails is `CLEAN_INCOMPLETE` |

Prints the launchd user agent that runs `refresh --auto`: `label` (`io.github.dividedby.sideload.refresh`), `path` (`~/Library/LaunchAgents/<label>.plist`), `plist` (the XML text), `install` (the commands that write it, lint it, load it with `launchctl bootstrap` and start it with `launchctl kickstart`) and `stop` (`touch $SIDELOAD_HOME/refresh.disabled`, `launchctl bootout`). The plist runs `<binary> refresh --auto` every 1800 s (`StartInterval`, `RunAtLoad` false, `ProcessType Background`, `LowPriorityIO`, `LimitLoadToSessionType Aqua`, no `KeepAlive`), stderr to `$SIDELOAD_HOME/logs/launchd-refresh.err`, stdout to `/dev/null`, and sets `SIDELOAD_HOME` only when it is not the default. `--binary` (default `~/.local/bin/sideload`) must be absolute. It takes no other option (`USAGE` with one). **Printing is not installing:** only the owner runs the printed commands; agents never run `launchctl` or `device auto-refresh`. The printed paths keep your real home directory (this is the one output that is not masked to `/Users/<user>`), because the plist needs it. |

## Turning on auto-refresh

Owner steps, in order (agents never run the `launchctl` or `device auto-refresh` steps). `refresh --auto` renews, on
the devices you opt in, the free-team installs with 5 days or fewer left, every 30 minutes while you are logged in.
It never installs an app the device does not have, and it stays silent unless something needs you (a notification for
each renewal attempt, and for an install it gives up on).

1. Put a release build where the agent will find it, and check it runs:

   ```sh
   swift build -c release --arch arm64
   mkdir -p ~/.local/bin
   rm -f ~/.local/bin/sideload
   cp "$(swift build -c release --arch arm64 --show-bin-path)/sideload" ~/.local/bin/sideload
   ~/.local/bin/sideload status
   ```

2. Opt a device in (writes `config.json` only): `~/.local/bin/sideload device auto-refresh --alias iphone --on --yes`.
3. Print the agent: `~/.local/bin/sideload refresh --print-agent` (add `--binary <absolute path>` if the binary is
   elsewhere). Read the `plist` and `install` fields; nothing has been written yet.
4. Run the `install` commands in order: they create `~/Library/LaunchAgents` and the logs folder, write the plist, lint
   it, `launchctl bootstrap gui/$(id -u) <plist>` and `launchctl kickstart -k gui/$(id -u)/io.github.dividedby.sideload.refresh`
   (the first run starts at once; later ones every 30 minutes).
5. Watch one cycle in `~/.sideload/logs/refresh.jsonl` (one JSON line per decision and step; the `run` line says how it
   ended) and `~/.sideload/logs/launchd-refresh.err` (launchd's stderr; normally empty). With nothing due, a run only logs
   `NOT_DUE`.

To pause, `touch ~/.sideload/refresh.disabled` (every run skips with `KILL_SWITCH`; `rm` the file to resume). To remove the
agent, `launchctl bootout gui/$(id -u)/io.github.dividedby.sideload.refresh` and delete the plist; to take a device
out, `device auto-refresh --alias iphone --off --yes`. After a new release build, `rm` the old binary, then copy the
new one in (copying over a signed binary in place can get it killed by macOS); the agent needs no reload. The menu bar app shows "Auto-renew off" under the rows of a device that is not opted in.

## Turning on expiry notifications

A backstop for auto-refresh: once a day at 09:00 (and once when it is loaded) `status --notify` posts a notification when a
free install gets down to 3 days, 1 day or expires, a paid certificate or profile reaches 60 or 14 days or expires, or an
app-data restore is waiting. Each is announced once per threshold, so a quiet day means nothing is due. It matters most
when auto-refresh cannot reach a device: `refresh --auto` skips a device it cannot see (`DEVICE_NOT_VISIBLE`) without a
notification, since that is not an attempt. Owner steps (agents never run the `launchctl` steps):

1. Use the same `~/.local/bin/sideload` as auto-refresh (step 1 above).
2. Print the agent: `~/.local/bin/sideload status --print-agent` (add `--binary <absolute path>` if the binary is
   elsewhere). Read the `plist` and `install` fields; nothing has been written yet.
3. Run the `install` commands in order; the last one, `launchctl kickstart -k gui/$(id -u)/io.github.dividedby.sideload.status`,
   runs it once at once.
4. Check `~/.sideload/logs/launchd-status.err` (normally empty). If nothing is due, no notification appears; to see what
   it would announce, run `~/.local/bin/sideload status` and look at `items`, `installs` and `pendingRestores`.

To remove it, `launchctl bootout gui/$(id -u)/io.github.dividedby.sideload.status` and delete the plist. macOS must allow
notifications from Script Editor (`osascript`), the same permission auto-refresh's notices use.

## Approving download sources

`fetch` downloads only from sources the owner lists in `approvedSources` in `$SIDELOAD_HOME/config.json`
(an empty list refuses everything). Each entry is the app key; an optional `hosts` list can only narrow the
built-in allowlist (api.github.com, github.com, objects.githubusercontent.com, release-assets.githubusercontent.com,
raw.githubusercontent.com, dl.strem.io), never add a host:

```json
"approvedSources": [{"app": "apollo"}, {"app": "stremio-ios"}, {"app": "stremio-tvos"}]
```

Then `sideload fetch --app stremio-ios` downloads and reports; after reviewing the output the owner runs
`sideload fetch --app stremio-ios --approve --version <v>` with the version it printed. Stremio's index is third-party (`gorlev`, no Stremio affiliation):
the hash it publishes protects against corruption or a swapped file, not against a malicious index author, so
every new version needs that approval.

## Portal audit key

`portal` needs an App Store Connect API key (App Store Connect > Users and Access > Integrations > Team Keys).
A Developer-role key may be enough for devices, App IDs and profiles; listing certificates may need Admin (the
section then reports `ASC_FORBIDDEN` and says so). Put the downloaded key and a small `key.json` in
`$SIDELOAD_HOME/asc/` (directory mode 0700, files 0600, owned by you, no symlinks):

```json
{ "keyId": "ABCDE12345", "issuerId": "<issuer UUID>", "keyFile": "AuthKey_ABCDE12345.p8", "role": "Developer" }
```

The tool signs a 10-minute token in process, sends only `GET` requests to `api.appstoreconnect.apple.com`,
and never prints the key or the token. Revoke the key in App Store Connect when you no longer need it.

## State and secrets

All state lives outside the repo in `$SIDELOAD_HOME` (default `~/.sideload`, mode 0700): `config.json`,
`ledger.json` (certificate/profile/export history: no secrets, fingerprints as 8 hex digits, devices as their
last 4 characters), `secrets/` (`secrets/p12/` holds the exported `.p12` masters, 0600; their password is only in the keychain), `exports/` (Feather kits from `export-cert`, created on first use), `asc/` (the portal API key you provide), `downloads/` (+ SHA-256 manifest), `builds/` (`carrier/` is the generated profile-carrier project, `signed/` holds the apps `sign` produced), `profiles/free/` (free-team profiles from `provision`, 0600; they contain device IDs, so they are never printed), `backups/` (app-data backups from `slot lend`, created on first use, 0700/0600; secrets-class, they hold session tokens), `logs/`, `evidence/` (opt-in canary
bundles, created on first use; certificate shown as the first 8 hex digits of its SHA-1 only). Certificates, keys, profiles, the `.p12`
password, device UDIDs and IPAs never enter the repo; the pre-commit hook (`scripts/check-secrets.mjs`) and
CI enforce this.
